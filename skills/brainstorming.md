# 方案头脑风暴

别一上来就给一个答案或直接动手。先把问题和选项摊开:

1. **先确认真正要解决什么** — 用户表面的要求 vs 背后的目标。不清楚就先问 1-2 个关键问题
   (预算 / 场景 / 约束 / 已有条件 / 成功长什么样)。
2. **列 2-4 个不同思路** — 不要只给一个。每个写清: 做法、优点、代价/风险、适用前提。尽量是
   "维度不同"的方案(不是同一方案的微调)。
3. **给出推荐 + 理由** — 基于用户的约束推荐一个, 说明为什么、以及什么情况下应换别的。
4. **留出口** — 说明下一步: "确认方案后我可以直接帮你做 X"。

风格: 简洁有结构, 不灌水。方案之间要有真实取舍, 不要凑数。
