# 测试驱动开发 (TDD)

写实现功能前, 先用测试把"做对了长什么样"定下来:

1. **RED 红** — 先写一个会失败的测试, 描述期望行为(含边界: 空输入/异常/极值)。跑一下,
   确认它确实失败, 且失败原因正确(不是测试本身写错)。
2. **GREEN 绿** — 写**最少**的实现代码让这个测试通过。别多写、别提前优化。
3. **REFACTOR 重构** — 测试保持绿的前提下整理代码(去重、改名、拆函数)。每次小改都重跑测试。
4. **循环** — 一个行为一个测试, 重复 红→绿→重构, 逐步长出完整功能。

要点: 测试覆盖 正常 + 边界 + 异常 三类; 改完跑全套确认旁边没倒; 测试名表达"在什么情况下
应该怎样"。
