# 系统化调试

别凭感觉乱改。按四步走, 每步都有依据:

1. **稳定复现** — 先找到能稳定触发问题的最小步骤/输入。复现不了就先收集证据(日志、报错
   全文、环境)。**改之前必须能复现**。
2. **定位范围** — 用二分法缩小: 是输入、还是处理、还是输出?加日志/打印关键中间值, 确认问题
   实际发生在哪一段, 而不是哪一段"看着像"。
3. **找根因** — 找到"为什么"会这样(而不是表面症状)。能说出"改 X 就好, 是因为 Y"这种可解释
   的因果, 才算找到根因。
4. **改 + 验证 + 查旁边** — 针对根因做最小改动; 改完用第 1 步的复现验证已修; 再快速看改动
   旁边没被带倒。

红线: 没复现不改; 没定位不猜; 一次只改一个变量, 便于判断是不是它起的作用。
